# BeatCounter Windows Build + MIDI CC Output Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build BeatCounter as a working Windows VST2 (64-bit), then add MIDI CC output so the detected running BPM is emitted as a MIDI CC message on every beat.

**Architecture:** The project is a JUCE 3.1.1 VST2 plugin built with Visual Studio. The processor already detects BPM and exposes it via `parameters["Running BPM"]`. We add a single new code path in `processBlock()` that fires a MIDI CC message (CC #20 on channel 1, value = clamped BPM) into the outgoing `MidiBuffer` whenever a new running BPM value is set. No new files are needed — all changes live in `Source/PluginProcessor.cpp` and `Source/PluginProcessor.h`.

**Tech Stack:** JUCE 3.1.1, VST2 SDK 2.4, Visual Studio 2022 (with v120 or v143 toolset), C++11, Windows x64.

## Task 4: Add MIDI CC Output for Running BPM

**Files:**
- Modify: `Source/PluginProcessor.h`
- Modify: `Source/PluginProcessor.cpp`

**What we're doing:** Every time `runningBpm` is updated (already inside an `if` block in `processBlock()`), we emit a MIDI CC message into the outgoing `MidiBuffer`. We use:
- **Channel:** 1 (index 0 in JUCE)
- **CC number:** 20
- **Value:** `(int)round(runningBpm)` clamped to 0–127. Since BPM 60–180 maps directly, this means CC value = BPM for typical DJ tempos. If you need decimals, use a 14-bit scheme (Tasks 5+).

The plugin already declares `pluginProducesMidiOut="1"` in the .jucer, so no project config change is needed.

- [ ] **Step 4.1 — Add member variable to PluginProcessor.h**

Open `Source/PluginProcessor.h`. In the `private:` section, after `unsigned long cooldownPeriodInSamples;`, add:

```cpp

    static const int kBpmMidiCcNumber = 20;
    // Tracks last emitted CC value to avoid flooding identical messages
    int lastEmittedBpmCc;
```

Full private section after change:

- [ ] **Step 4.4 — Emit MIDI CC in processBlock() when runningBpm is updated**

In `Source/PluginProcessor.cpp`, find this block inside `processBlock()` (around line 90):

```cpp
                            runningBpm /= (double)bpmHistory.size();
                            bpmHistory.clear();
                            numSamplesProcessed = 0;
                            parameters.set("Running BPM", runningBpm);
```

Add the MIDI CC emit **immediately after** `parameters.set("Running BPM", runningBpm);`:

```cpp
                            runningBpm /= (double)bpmHistory.size();
                            bpmHistory.clear();
                            numSamplesProcessed = 0;
                            parameters.set("Running BPM", runningBpm);

                            // Emit MIDI CC 20 with clamped BPM value
                            int bpmCcValue = (int)round(runningBpm);
                            if(bpmCcValue < 0)   bpmCcValue = 0;
                            if(bpmCcValue > 127) bpmCcValue = 127;
                            if(bpmCcValue != lastEmittedBpmCc) {
                                MidiMessage ccMsg = MidiMessage::controllerEvent(1, kBpmMidiCcNumber, bpmCcValue);
                                midiMessages.addEvent(ccMsg, i);
                                lastEmittedBpmCc = bpmCcValue;
                            }
```

**Why `i` as the sample offset?** JUCE `MidiBuffer::addEvent` needs a sample position within the current buffer. Using `i` (the current sample index in the outer for-loop) places the CC at the exact moment the beat was detected.

## Optional Task 6: 14-bit High-Res BPM CC (CC 20 MSB + CC 52 LSB)

If you need sub-integer BPM precision (e.g., 128.4 BPM), you can encode the BPM as a 14-bit value across two CCs using the MIDI 14-bit CC convention (CC 0–31 = MSB, CC 32–63 = LSB for the same parameter, where LSB = CC + 32).

**Encoding:** BPM is multiplied by 100 to get an integer (12800 for 128.00 BPM), then split:
- MSB = value >> 7 (upper 7 bits) → CC 20
- LSB = value & 0x7F (lower 7 bits) → CC 52

**Decoding (receiver side):**
```python
bpm = ((msb << 7) | lsb) / 100.0
```

- [ ] **Step 6.1 — Update PluginProcessor.h**

Replace the MIDI CC section added in Task 4:
```cpp
    // 14-bit BPM output: CC 20 (MSB) + CC 52 (LSB), value = BPM * 100
    static const int kBpmMidiCcMsb = 20;
    static const int kBpmMidiCcLsb = 52;  // = 20 + 32, per MIDI 14-bit convention
    int lastEmitted14BitBpm;  // replaces lastEmittedBpmCc
```

- [ ] **Step 6.2 — Update constructor and clearBpmHistory()**

In constructor: `lastEmitted14BitBpm = -1;`  
In clearBpmHistory(): `lastEmitted14BitBpm = -1;`

- [ ] **Step 6.3 — Replace CC emit block in processBlock()**

Replace the block added in Task 4 Step 4.4 with:
```cpp
                            // 14-bit BPM CC output (BPM * 100 encoded across CC 20 + CC 52)
                            int bpm14bit = (int)round(runningBpm * 100.0);
                            if(bpm14bit < 0)      bpm14bit = 0;
                            if(bpm14bit > 16383)  bpm14bit = 16383;  // 14-bit max
                            if(bpm14bit != lastEmitted14BitBpm) {
                                int msb = (bpm14bit >> 7) & 0x7F;
                                int lsb = bpm14bit & 0x7F;
                                MidiMessage msbMsg = MidiMessage::controllerEvent(1, kBpmMidiCcMsb, msb);
                                MidiMessage lsbMsg = MidiMessage::controllerEvent(1, kBpmMidiCcLsb, lsb);
                                midiMessages.addEvent(msbMsg, i);
                                midiMessages.addEvent(lsbMsg, i + 1);  // +1 sample to preserve order
                                lastEmitted14BitBpm = bpm14bit;
                            }
```
